# Codex Dispatch Preflight

<!-- Codex-SPECIFIC --> Read on Codex before the first native fix-phase subagent spawn (investigator, challenger, verifier) or any same-agent investigation or verification fallback. Other hosts skip this file.

**Codex preflight before fallback:** <!-- Codex-SPECIFIC --> When AIVV is running inside a Codex agent session, a missing visible `spawn_agent` tool is not by itself a capability failure. Before same-agent investigation or same-agent verification fallback, run this preflight: confirm the relevant TOML exists under `<codex-home>/agents/` or project `.codex/agents/`, checking both scopes before declaring TOML missing, and if the dispatch tool is not already loaded, use `tool_search` with `multi-agent subagent dispatch codex agents spawn_agent wait_agent close_agent`. If discovery returns `spawn_agent` / `wait_agent`, use cold subagent dispatch and do not record a dispatch degradation; if `close_agent` is absent, keep dispatch available but record cleanup as a lifecycle degradation per the Codex adapter. Explicit `/aivv-fix`, `$aivv-fix`, `/aivv --fix`, and `$aivv --fix` invocations authorize AIVV-owned read-only investigator/verifier subagents; do not require a second delegation phrase. If Codex host policy still blocks delegation despite visible dispatch tools and existing TOML, ask once for explicit delegation permission or halt with `codex-subagent-delegation-blocked`; do not silently continue as same-agent investigation/verification. When AIVV is running outside Codex and merely calls `codex exec` as a provider subprocess, this preflight does not apply; that is multi-model provider dispatch, not native Codex subagent dispatch.
